# Visual Pilot: Steel & Ember

## Scope

Open `/?visual=pilot` under the Vite base URL. This is an isolated, optional art/motion trial, not a replacement for the production battle renderer. It never mounts `useBattle`, and it does not save battles, inventory, achievements or learning progress. Locale handling remains shared with the app.

The trial uses the existing `genQ` and `calcAttackDamage` utilities but deliberately simplified local turns (100 player HP, 180 enemy HP, 18 enemy damage). These values are demonstration scaffolding, not production balance changes. Preview buttons play the same beats without damage. Original/new comparison changes only presentation.

## Runtime

- Two transparent WebP atlases, each 2048x768, four columns and two rows. Each cell is 512x384. The lowest visible pixels share the y=368 floor baseline. Each atlas uses one packing scale; runtime never resizes individual poses.
- Row-major poses: idle, inhale, anticipation, strike, follow-through, recovery, recoil, braced recovery.
- CSS background-position keyframes select poses. Continuous transform tracks add anticipation, acceleration, a short contact hold, follow-through and a damped return. Adjacent beats share exact position/rotation/scale endpoints; sprite-pose endpoints also match. React advances only on action beats, not on animation frames.
- Idle uses one stable pose with an independent, continuous breathing layer pivoting around a registered support-foot X coordinate and the shared floor baseline. The wolf and dragon have different periods and phases. This layer stays mounted through combat beats, so breathing does not restart when a pose changes. It is a subtle whole-image deformation, not articulated limb or wing animation.
- Claw strokes draw on with four short contact sparks and an expanding impact ring. Breath has a shaped outer flame, core, ribbon and muzzle glow instead of a triangular cone. The blast reaches the target on the impact beat; only its width/envelope animates, avoiding delayed visual contact after HP has already changed. Mouth/impact anchors are stored in cell pixels and transformed for the mirrored actors; damage labels share those impact anchors. No cross-fades, extra textures, animation library, per-frame React state or new background loops are used. The existing 340/520 ms pre-impact deadlines and damage rules are unchanged.
- The reducer owns impact/HP changes. Delayed actions carry cycle and phase tokens so reset cannot apply an old hit.
- Pause and hidden-document suspension preserve remaining deadlines and pause CSS animations. Reduced-motion CSS disables idle movement, displacement and flashes while preserving discrete combat state.
- Inspect poses pauses the combat clock and displays all eight drawings with floor/support-foot guides. It overrides presentation only, without cancelling CSS animations or touching HP, so leaving inspection restores the previous beat and its remaining time. Reset clears inspection. Original-sprite comparison exits inspection.
- Header/HUD, battlefield and controls have separate layout regions. A fixed control-region height prevents question transitions from resizing the battlefield; viewport-height-aware actor widths reserve space for every pose.
- This lazy trial decodes both assets when opened, with original-sprite fallback on decode failure. Production battles instead load only the atlases of actors actually present; the original PNG files are unchanged.
- V2 atlas transfer is 627,982 bytes combined (about 613 KiB); decoded RGBA storage is still 12 MiB for both atlases, before browser overhead. V1 files remain as non-destructive references and are not loaded by this screen. This is not an FPS or whole-game performance measurement.

## Production Rollout: Batch 1

The approved first batch enabled `player_wolf2` and `boss_crazy_dragon` in normal battles, not only the trial route. There are 51 visual forms (21 starter stages, 25 ordinary enemy forms/variants and five Boss forms). Batch 2 subsequently added `player_wolf0` and `player_wolf1`, so current coverage is **4 of 51**, with 47 remaining original. See [Wolf Batch 2](wolf-animation-batch2.md) for its assets, preparation and prompts. Menus, the encyclopedia and Boss intro portraits retain original art. No unlock, progression or save migration is required.

- `src/data/spriteAnimationAssets.ts` is the opt-in registry shared with the trial. Sprite factory identities resolve actual stages, including selectable PvP Bosses; enemy active/evolved keys and dark-dragon phase-2 overrides remain authoritative.
- `BattleArenaSprites` passes each physical slot's resolved animation to `BattleSprite`. It never infers the attacker from global `playerAtk`, the active co-op role or the player's species. Main/sub and PvP sides can attack or recoil independently.
- All eight silhouettes are uniformly fitted to the original profile's visual envelope. The fit uses their union, not current-pose bounds. Original safe-placement, facing transforms, stable impact anchors, continuous body motion and defeat dissolves remain in use. This intentionally favors full visibility over enlarging the new drawings.
- CSS steps switch only the drawings; there are no new per-frame JS loops or gameplay timers. Idle keeps frame 0 with the existing breathing layer. Attack uses 0/1/2/3/4/5/0, hurt uses 6/7/5/0, and dodge uses 7/5/0. Charge and defeat hold the appropriate key pose. Reduced motion uses a static action pose; low-performance mode retains action poses and removes existing ambient motion.
- Enemy lunge duration now matches its existing scheduled clear: 500ms normal, 380ms assist, 320ms PvP. Previously its fixed 600ms CSS motion was cut short. Damage timing and game rules are unchanged.
- Each mounted upgraded actor decodes its atlas before replacing the original; failed or wrong-size atlases remain original. No all-roster preload is added. Both atlases together transfer 627,982 bytes and decode to 12 MiB RGBA before browser overhead; identical URLs can share browser caching. This is not a measured FPS gain or a physical-phone memory guarantee.
- Battle pause freezes both sprite-body animation and atlas steps. Impact freeze includes the atlas. The isolated trial retains its own inspection/slow-motion controls and does not drive production state.

Verification: 762 automated tests, TypeScript/lint checks and build budgets pass. Browser checks mounted the real `BattleScreen` with no-save fixtures at 1280x720, 390x844, 320x568 and 844x390, exercising two/four actors, PvP reversed sides, independent main/sub attacks, pause/resume, low-performance mode and original-form fallback. A deliberately missing wolf atlas kept the original PNG while the dragon continued using new art. This does not replace playing every encounter on physical devices. The temporary fixture is not shipped.

## Art Provenance

Generated with the built-in image generation tool, using the project's original `boss_crazy_dragon.png` and `player_wolf2.png` as identity references. The dragon's generated atlas was also used as the wolf's style reference. The first sheets had opaque checkerboards. The dragon received an image-tool alpha extraction; the wolf received user-approved programmatic neutral-background removal and a one-pixel alpha defringe. User-approved processing also cropped the eight nonuniform source regions, aligned their feet, preserved one shared scale, packed atlases and encoded WebP at quality 90. No per-pose resizing or generated in-between frames.

### V2 Refinement

The wolf's original RGB sheet was reprocessed from source. The old per-pixel brightness key had mistakenly removed neutral white highlights inside the fur. The new matte removes four-connected neutral regions (minimum channel >=220, channel spread <=20) touching the crop border, plus large enclosed regions over 500 pixels, while retaining small isolated fur highlights. A one-pixel edge defringe follows. These thresholds are specific to this source, not a general-purpose background-removal system.

Only wolf pose 6 was redrawn with the built-in image tool to keep its muzzle facing its opponent during recoil. The edit returned real RGBA. Its separate-resolution crop was first matched to the source drawing scale (height 273 pixels, about 1.06x the idle drawing height), then packed together with the other seven frames at one shared 0.95 scale. The dragon keeps its existing drawings at scale 1; no new dragon illustration was generated.

Horizontal registration now uses a visually reviewed support-foot anchor rather than the center of the entire silhouette, so stretching the cape, wing or tail does not automatically move the body. The wolf's anchor is x=368; the dragon's is x=300. Both actors are mirrored at runtime. These are X anchors plus a common lowest-pixel floor line, not a full skeletal registration of every paw. Every frame reserves at least 12 pixels of visible edge clearance. V2 WebP encoding uses quality 92. `registration-v2.json` records source-foot X positions, packing offsets, visible bounds, the common scale, sizes and SHA-256 hashes; tests check it against the shipped files.

Source images are preserved under the image tool's generated-images directory for this task: `exec-70ac5b1f-ec3a-4cf0-9552-3afcadbc07e4.png` (wolf RGB sheet) and `exec-318e062d-07eb-4c8f-b8f0-37dc0c97760f.png` (corrected recoil). The dragon v2 was packed from v1. Preparation used user-approved Python/Pillow/NumPy tooling outside the browser; no processing dependency was added to the game.

## Known Limitations

This is an eight-key-pose art study with continuous secondary motion, not finished frame-by-frame or skeletal animation. It reduces held-pose stiffness and silhouette-centering jumps, but the drawings themselves still change discretely, especially visible in slow motion. The generated drawings still vary in anatomy and decoration; support-foot registration cannot fix those differences. Precise limb continuity, final edge cleanup and art-direction approval remain necessary before a full-game rollout. The trial currently does not include co-op, production Boss mechanics, production attack FX or sound. Browser responsive checks are not physical-phone performance measurements.
